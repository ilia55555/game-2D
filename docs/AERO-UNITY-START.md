# AERO — اجرای پروژه و اتصال مدل‌های Blender

این نسخه طرح تصویر مرجع را به کمپین Unity 2.5D تبدیل می‌کند: شش محیط، شش سلاح، شش باس و VEXAR با سه فرم. مدل‌ها و بافت‌های نهایی کاربر هنوز در ریپو نیستند؛ جایگاه‌های خالی با حجم‌های موقت سه‌بعدی اجرا می‌شوند. عکس مرجع به‌عنوان تکسچر یا مدل بازی استفاده نشده است.

## باز کردن و اجرا

1. تغییرات PR را به شاخهٔ `games` Merge کن، یا خود شاخهٔ PR را دانلود کن. ZIP را کامل استخراج کن.
2. در Unity Hub روی **Add → Add project from disk** بزن و **پوشهٔ `Unity` داخل ریپو** را انتخاب کن.
3. نسخهٔ ثبت‌شدهٔ پروژه **6000.6.2f1** است. تغییر اجباری نسخه یا پکیج جدیدی انجام نشده است. تنها پکیج‌های عمومی Input System و Test Framework و ماژول‌های داخلی لازم‌اند؛ AI Assistant و Rider وابستگی پروژه نیستند.
4. منتظر پایان Import و دریافت پکیج‌ها بمان. صحنهٔ `Assets/Velocity/Scenes/Main.unity` را باز کن؛ منوی **AERO → Open Game** هم همین کار را می‌کند. در پروژهٔ تازه، صحنه در صورت خالی و ذخیره‌نشده‌نبودن صحنهٔ فعال، خودکار باز می‌شود.
5. **Play → Continue journey**. انتخاب مرحله‌های بعد پس از تمام‌کردن مرحلهٔ قبلی باز می‌شود.

نسخهٔ قدیمی Godot در `Godot/` نگه داشته شده است. آن پوشه را در Unity باز نکن.

## کنترل‌ها

| عمل | کیبورد / ماوس | دسته |
|---|---|---|
| حرکت | A/D یا چپ/راست | استیک چپ / D-pad |
| پرش و پرش دوم | Space، W یا بالا | A |
| شلیک | J، Z یا کلیک چپ | X |
| دش | Shift، K یا X | B |
| تعویض سلاح | Q/E یا 1 تا 6 | RB |
| نشستن | S یا پایین | پایین D-pad |
| توقف | Esc یا P | Start |
| تمام‌صفحه | F11 | — |

لیزر: شلیک را نگه دار و رها کن. نوار Charge میزان شارژ را نشان می‌دهد. شش سلاح از ابتدا برای آزمایش در دسترس‌اند. انرژی سلاح‌ها مشترک است و بازسازی می‌شود؛ اگر کافی نباشد، همان شلیک با تفنگ اصلی انجام می‌شود. یخ دشمن عادی را منجمد و باس را موقتاً کند می‌کند. لیزر چند هدف را می‌زند ولی از دیوار رد نمی‌شود. انفجار موشک و پلاسما به هدف اصلی دو بار آسیب نمی‌زند و پشت دیوار آسیب نمی‌دهد.

منوها با ماوس/لمس کار می‌کنند؛ کنترل دسته برای گیم‌پلی است. Touch Controls در Settings دکمه‌های حرکتی را فعال می‌کند. تنظیمات و رکورد مرحله‌ها روی دستگاه ذخیره می‌شوند؛ ادامه از چک‌پوینت مربوط به همان نوبت بازی است، نه بازکردن دوبارهٔ برنامه.

## ورود کاراکتر از Blender

1. مدل و تکسچرها را به‌صورت FBX در `Assets/Velocity/Models/` وارد کن. برای خرگوش و حیوان‌ها **Rig → Animation Type: Generic** مناسب قرارداد این پروژه است. انیمیشن‌ها را In-place بساز؛ حرکت واقعی ریشه را کد کنترل می‌کند.
2. در **AERO → Art Setup**، تب Actors، فایل FBX یا Prefab را در نقش مربوط بینداز. `hero` قهرمان است؛ `boss_gorilla` و بقیه نام‌ها در جدول پایین‌اند.
3. مدل باید روی پا بایستد، محور بالای آن +Y و جهت نگاه پایهٔ آن +X باشد. دوربین از سمت Z منفی نگاه می‌کند؛ حرکت روی X/Y و Z=0 است. Rotation و Scale را در همین پنجره تنظیم کن. **Fit gameplay height** مدل را روی زمین می‌نشاند و اندازهٔ تقریبی مناسب می‌دهد؛ سپس تناسب بدن و Collider را در Play بررسی کن.
4. در Import Settings فایل FBX، **Import Animation** را روشن کن. برای Idle و Run گزینهٔ Loop Time را فعال کن. برای Attack، Hurt، Death و Transform خاموش باشد.
5. کلیپ‌ها را با نام‌های جدول بعدی صادر کن و **Build Animator from FBX clips** را بزن. کنترلر جدید ساخته و به همان نقش وصل می‌شود. اگر کنترلر خودت را ساخته‌ای، آن را در Animator controller قرار بده. هر بار تولید کنترلر، یک فایل جدید می‌سازد و فایل قبلی را بازنویسی نمی‌کند.
6. **Save catalog** و شروع مجدد مرحله. تغییرات Catalog روی کاراکترهای تازه ساخته‌شده اعمال می‌شود.

| کلیپ | استفاده |
|---|---|
| `Idle` / `Stand` | ایستادن |
| `Run` / `Walk` | حرکت |
| `Jump` / `Rise`، `Fall` | بالا رفتن / افتادن |
| `Crouch` / `Duck`، `Dash` | نشستن / دش |
| `Fire` / `Shoot` | شلیک |
| `Hurt` / `Hit`، `Death` / `Die` | آسیب / مرگ |
| `Telegraph`، `Attack`، `Slam`، `Special` | اخطار و حملات دشمن / باس |
| `Transform` | تغییر فرم VEXAR |

نام‌هایی مثل `Armature|Idle` یا `Rabbit_Run` هم تشخیص داده می‌شوند. برای حلقه و طول زمانی حمله‌ها بازبینی دستی لازم است؛ ابزار، مفهوم انیمیشنِ بدون نام را حدس نمی‌زند. کلیپ‌های نبودنی باعث توقف گیم‌پلی نمی‌شوند. مدل جایگزین باید Animator و Avatar معتبر داشته باشد؛ کد Avatar یا Rig را از یک تصویر تولید نمی‌کند.

پارامترهای کنترلر سفارشی:

- Float: `Speed`, `VerticalSpeed`, `Charge`, `Weapon`
- Bool: `Grounded`, `Crouching`, `Dashing`, `Charging`, `Shielded`, `Dead`
- Trigger: `Jump`, `Fire`, `Hurt`, `Death`, `Telegraph`, `Attack`, `Slam`, `Special`, `Transform`

Collider و Rigidbody داخل مدل‌های نمایشی غیرفعال می‌شوند و Root Motion خاموش است. Collider اصلی روی ریشهٔ گیم‌پلی می‌ماند؛ چرخش و مقیاس مدل، کنترل حرکت را عوض نمی‌کند.

## تفنگ، دست و مبدأ تیر

- روی استخوان دست، یک Transform با نام دقیق **`WeaponSocket`** قرار بده. مدل سلاح به آن وصل می‌شود.
- در نوک هر سلاح، Transform **`Muzzle`** بساز. جهت پایهٔ تفنگ باید در فضای ساکت +X باشد. Rotation جایگاه سلاح برای تنظیم تفاوت جهت استخوان‌هاست.
- هر سلاح را در تب Weapons به `weapon_blaster`, `weapon_scatter`, `weapon_laser`, `weapon_rocket`, `weapon_ice`, `weapon_plasma` وصل کن.
- اگر تفنگ بخشی از خود کاراکتر است، یک `Muzzle` روی همان مدل بگذار. برای مشخص‌کردن دستی استخوان‌ها، کامپوننت **ActorRig** دارای Animator، WeaponSocket، Muzzle و BuiltInWeaponParts است. قسمت‌های تفنگ قدیمی در BuiltInWeaponParts با نصب تفنگ جدا مخفی می‌شوند.
- اگر سلاح جدا نداشته باشی، همان تفنگ روی مدل نمایش داده می‌شود؛ تغییر نوع تیر همچنان کار می‌کند.
- مش یا افکت تیر در تب Projectiles متصل می‌شود. جهت پایهٔ آن +X است. تیر دقیقاً از مختصات Muzzle، روی صفحهٔ Z=0 ساخته می‌شود. برخورد سریع با SphereCast بررسی می‌شود.

## بکگراند، مسیر و طراحی مرحله

محیط سه‌بعدی را Prefab کن و در `environment_0` تا `environment_5` بگذار. مختصات یک واحد = یک متر است. برای نمونه، طول مرحلهٔ اول ۱۰۴ متر و محوطهٔ باس آن از X=84 تا X=104 است. بکگراند را معمولاً در Z مثبت بچین؛ برخوردهای محیط نمایشی غیرفعال‌اند و برخوردها را سکوهای بازی تعیین می‌کنند.

برای تغییر مسیر بدون نوشتن JSON:

1. **AERO → Stage Layout Editor**، مرحله را انتخاب و **Create new editable layout from shipped route** را بزن.
2. یک Prefab جدید با همهٔ سکوها، دشمن‌ها، سکه‌ها و تله‌ها ساخته و به `layout_N` وصل می‌شود. در Prefab Mode گزینهٔ Gizmos را روشن کن.
3. آبجکت‌های LevelMarker را روی X/Y جابه‌جا کن. نقطهٔ Floor/Platform لبهٔ چپ سطح بالای سکو است. Width بر حسب متر است. برای Moving، دامنه و دوره را مشخص کن. برای دشمن EnemyKind را مطابق جدول تنظیم کن.
4. ریشه و نشانگرها را نچرخان و Scale را 1 نگه دار. سه چک‌پوینت و سه Relic را نگه دار. سمت راست هر چک‌پوینت حداقل ۰٫۷ متر زمین امن لازم است. از ArenaStart تا Length یک Floor پیوسته در Y=0 نگه دار. Spawn و BossSpawn از کامپوننت StageLayout قابل تغییرند.
5. **Validate layout**، سپس Save و اجرای دوبارهٔ مرحله. محیط بلندر را هم با مسیر جدید هماهنگ کن. خود نشانگرهای Layout در بازی نمایش داده نمی‌شوند.

نسخهٔ کدنویسی طرح پایه در `tools/build_aero_campaign.py` و خروجی‌اش `Assets/Velocity/Resources/Velocity/campaign.json` است. `export_unity_campaign.py` و `setup_unity_files.py` ابزارهای مهاجرت قدیمی‌اند؛ برای بازسازی AERO از آن‌ها استفاده نکن.

## تست و خروجی

در یونیتی: **AERO → Validate Project** و سپس **Window → General → Test Runner**، هر دو EditMode و PlayMode را اجرا کن.

برای اجرای خودکار روی ویندوز، ابتدا پروژه را در Editor ببند، سپس از ریشهٔ ریپو:

```powershell
.\tools\test_unity.ps1 -UnityEditor "E:\App\UnityTemp\Editor\Unity.exe"
```

اگر مسیر نصب تغییر کرده، آدرس واقعی Unity.exe را بده. گزارش در `Unity/TestResults` نوشته می‌شود. در این محیط توسعه Unity نصب نبود؛ تست‌های موتور نوشته شده‌اند اما اجرا نشده‌اند. گزارش دقیق در [UNITY-VALIDATION.md](UNITY-VALIDATION.md) است.

خروجی ویندوز: **AERO → Build Windows**؛ فایل در `Unity/Builds/Windows/AERO.exe` ساخته می‌شود. ماژول Build Support مربوط باید در Unity نصب باشد. برای لینوکس، Build Linux موجود است.

نسخهٔ هنری نهایی به ورود مدل، بافت، نورپردازی و انیمیشن‌های تو و یک دور بازی‌کردن واقعی برای تنظیم سختی نیاز دارد. این تحویل کد و مراحل قابل‌آزمایش را فراهم می‌کند و ادعای اجرای موفق موتور یا خروجی نهاییِ تست‌شده ندارد.
